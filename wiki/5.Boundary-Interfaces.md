# Boundaries

There is no HTTP API. Callers are YAML cases, the CLI, environment
variables, and the NPZ archive.

## Case YAML

Set `LINSTABPY_CASE_CONFIG` to the YAML path (aliases
`LINSTABPY_CASE2_CONFIG`, `LINSTABPY_CASE1_CONFIG`). The file names the
packed-field path, physics (`Re`, `Ma`, `Pr`, `kappa`, `T_0`), numerics
(`fd_order`, strides, `beta`), BC recipe list, and solver subsections.

BC recipes are lists of dictionaries. `BCRecipe` normalizes them.

## CLI

```bash
python -m linstabpy.driver.cli --version
LINSTABPY_CASE_CONFIG=path/to/case.yaml python -m linstabpy.driver.cli
```

`--version` does not start PETSc. Cache skip: `LINSTABPY_FORCE_RECOMPUTE=1`.

## Environment (selected)

| Variable | Role |
|---|---|
| `LINSTABPY_CASE_CONFIG` | YAML path |
| `LINSTABPY_FORCE_RECOMPUTE` | Skip NPZ cache |
| `LINSTABPY_FACTOR_BACKEND` | Sparse-direct backend after YAML |
| `LINSTABPY_EIGEN_PC_FACTOR_SOLVER_TYPE` | Per-solver factor override |
| `LINSTABPY_BUILD_STACK` | Installer stack (`default`, …) |
| `LINSTABPY_STAGE_HEARTBEAT_SECONDS` | Long-stage keep-alive (default 30) |
| `LINSTABPY_FLOQUET_SHIFT` | Floquet shift if not in YAML |
| `LINSTABPY_CASE_LOG_PREFIX` | Log tag for concurrent studies |

## Runtime NPZ

One compressed `.npz` per run through `linstabpy.driver.io.save_results`.
Checked keys: `RUNTIME_NPZ_CONTRACT_KEYS` in `driver.payload`. Additive
fields are acceptable. Renames or removals need a migration note, tests,
and reader updates.

Groups (see `docs/runtime_npz_contract.md`):

- Spectra and resolvent: `omega`, `direct_modes`, `gains`, `responses`, `forcings`, `St`, `beta`
- Mesh and weights: `X`, `Y`, `U`, `sponge`, `W_diag`, `invW_diag`, `fd_order`, `alpha_filter`
- BC provenance: `bc_indices`, `bc_effective_dirichlet_indices`, `bc_column_zeroed_dirichlet_indices`, …
- Stability metadata, postcheck, acceptance
- Numerics flags, `provenance_config_hash`, `provenance_linstabpy_git_sha`
- Cost keys merged by `save_results` from `collect_cost_metrics`
