   1. `tools/parity/compare_martini_examples.py`
   2. Inputs: `martini_cases.jsonc`, extracted MATLAB NPZ bundles, and Python example NPZ artifacts.
   3. Outputs: consolidated JSON report and paper-ready CSV rows.
2. Comparison policy is case-specific, because the examples do not expose one common artifact schema:
   1. Example 0: protocol-level derivative verification only. Report the MATLAB self-check fields/logs plus the shipped Python curvilinear-validation status, and label this row as not being a direct field overlay.
   2. Examples 1, 2, 5: resolvent gains plus leading response/forcing mode comparisons after phase alignment.
   3. Example 4: direct/adjoint spectrum parity plus leading mode comparisons.
   4. Example 3: record `UNAVAILABLE` because no MATLAB exports are present in `martini_examples/`.
3. Status classes:
   1. `PASS`
   2. `SOFT_FAIL`
   3. `HARD_FAIL`
   4. `UNAVAILABLE`
4. Hard failures are for missing required artifacts or incompatible shapes/keys.
5. Soft failures are numerical mismatches with field-level diagnostics retained in the JSON report.
