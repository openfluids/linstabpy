# Plan: Strategy B scalability + full MATLAB matrix equivalence

Date: 2026-02-26  
Repo: `linstab2d`

## Objective

Deliver a production-ready iterative PETSc/SLEPc path (Strategy B) **without changing physics**, by first enforcing matrix-level equivalence with the MATLAB reference and then scaling to MPI runs.

## Definition of done (strict)

1. Python and MATLAB operators match for the Hamada parity case at matrix level (structure + values) for all required blocks/operators.
2. Eigen-spectrum parity remains within agreed tolerances after the matrix refactor.
3. Strategy B converges with explicit PETSc/SLEPc convergence reasons in distributed mode (`MPI>1`) on the parity case.
4. README and run scripts document one known-good baseline per strategy with reproducible commands.

## Scope

- In scope:
- Operator assembly parity (all LNSE terms, coordinate transforms, BC enforcement, penalties, indexing/order).
- PETSc assembly path for scalable iterative solving.
- Solver configuration and convergence diagnostics.
- Out of scope:
- New physics models.
- Broad feature additions unrelated to parity/scaling.

## Workstream A: Matrix equivalence with MATLAB (first priority)

### A0. Freeze parity target
- Canonical case: `example_6_hamada`.
- Fixed grid/order/parameters and variable ordering contract.
- Record exact MATLAB reference artifacts used for comparison.

### A1. Define matrix parity contract
- Compare these matrices/operators explicitly (as applicable to the case):
- `L0` (temporal operator after BCs).
- Pre-BC operator (assembly-only snapshot).
- Any split blocks used in spatial/temporal formulations (`LHS/RHS`, `L1/L2/R` when present).
- Contracts to enforce:
- Same DOF ordering and block layout (`rho,u,v,w,T`).
- Same BC row policy (identity/penalty/zeroing conventions).
- Same sparsity pattern for corresponding matrices.
- Same coefficient scaling/sign conventions.

### A2. Add deterministic matrix dump tools
- Python: export CSR triplets + metadata (shape, nnz, row ownership, block map) before and after BC.
- MATLAB: consume Gabriel/Hamada exports in the same normalized format.
- Store parity artifacts under `artifacts/parity/`.

### A3. Implement matrix diff diagnostics
- Structural diff:
- row nnz histogram mismatch,
- missing/excess nonzero coordinates,
- per-block sparsity mismatch.
- Value diff:
- max/mean abs error,
- max/mean rel error,
- row-wise top-k error rows,
- BC-row-only error report.

### A4. Close parity gaps term-by-term
- Reconcile in this order:
1. Coordinate/Jacobian and metric terms (curvilinear transformations).
2. Convective and viscous linearized terms.
3. Thermodynamic coupling terms.
4. BC and sponge enforcement rows.
5. Any variable ordering/permutation mismatch.
- After each fix, rerun matrix parity gate before moving on.

### A5. Matrix parity gate
- Gate passes only if:
- structural mismatch count = 0 (after agreed permutation),
- value errors within strict tolerance (target: near machine precision on normalized matrices),
- BC rows explicitly validated.

## Workstream B: Strategy B (scalable PETSc/SLEPc)

### B0. Remove risky matrix transfer path
- Replace global `scipy_to_petsc` handoff for large runs with ownership-aware PETSc assembly.
- Assemble PETSc AIJ by local row ranges (`rstart:rend`) to avoid replicated CSR memory.

### B1. Establish one iterative baseline (keep simple)
- Baseline profile:
- `EPS=KRYLOVSCHUR`, `ST=SINVERT`,
- `KSP=FGMRES`, `PC=BJACOBI`,
- sub-KSP `PREONLY`, sub-PC `LU`,
- strict `-st_ksp_error_if_not_converged`.
- Keep JD/PRECOND and advanced variants disabled until baseline is stable on `MPI>1`.

### B2. Conditioning/stability helpers
- Add matrix scaling/equilibration option before iterative solve.
- Keep logs for KSP iterations/residual behavior and rejected solves.

### B3. Advanced preconditioning (after baseline passes)
- Introduce `PCFIELDSPLIT` with physics blocks:
- fluid block `[rho,u,v,T]`,
- decoupled `w` block.
- Promote to default only if it improves robustness/performance while preserving parity.

### B4. Strategy B gate
- Must satisfy all:
- convergence reason present and valid (`MPI>1`),
- parity vs MATLAB spectrum still passes,
- memory behavior acceptable per-rank (no replicated full matrix),
- runtime documented.

## Execution order

1. Build/lock matrix parity tooling and artifacts (A0-A3).
2. Fix assembly mismatches until matrix gate passes (A4-A5).
3. Replace matrix transfer with local PETSc assembly (B0).
4. Stabilize iterative baseline on `MPI>1` (B1-B2).
5. Add fieldsplit optimization path (B3).
6. Update docs/scripts with known-good commands and gates (B4 + README).

## Deliverables

- `artifacts/parity/*` matrix parity reports (structure + values).
- Updated solver path with ownership-aware PETSc assembly.
- Documented Strategy A and Strategy B reproducible commands in `README.md`.
- Final parity evidence: matrix-level + spectrum-level for Hamada case.

## Risks and mitigations

- Risk: hidden permutation/order mismatch gives false value errors.
- Mitigation: explicit permutation map and block-index metadata in artifacts.
- Risk: iterative non-convergence blamed on solver while matrix is still inconsistent.
- Mitigation: matrix parity gate is mandatory before Strategy B tuning.
- Risk: memory blow-up from duplicated CSR.
- Mitigation: local-row PETSc assembly only for scalable path.
